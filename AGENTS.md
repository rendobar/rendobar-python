# Working in rendobar-python

For coding agents changing this SDK. Users of the SDK want the README.

- `src/rendobar/_generated/` is generated by Fern from `fern/openapi.json` (the
  published spec) plus `fern/overrides.yml`. Never edit either: the overrides are
  derived from the spec by `fern/derive_overrides.py` (strict per-type submit
  TypedDicts in `SubmitTypedJob`, open enums in jobs as `str`). Regenerate:
  `python fern/derive_overrides.py && (cd fern && fern generate --local --group python --force) && python fern/postprocess.py`
  (needs Docker; on Windows run it in WSL), then `python fern/postprocess.py`, which
  closes request enums, opens response enums to `Literal | str` and turns `Any` in
  models into `object`. CI checks both steps are current.
- Hand-written code is everything else in `src/rendobar/`: `_client.py`,
  `_async_client.py`, `_errors.py`, `_models.py`, `webhooks.py`. `_models.py` gives
  the generated models users meet their public names (`JobComplete`, not
  `Job_Complete`) without editing `_generated`. Every public method has a precise
  return type: `tests/typing_check.py` pins them, and the submit mistakes that must
  stay errors, under pyright strict and mypy --strict. Update it with any signature
  change. Every hand-written module starts with `# pyright: strict`.
- Submits take one job (`SubmitJob` typed dict, or `UntypedJob` for a type the
  SDK does not know) plus keyword options. Never add a second way to submit. Keep sync and async in step:
  everything that is not I/O lives in `_client.py` helpers (`core_options`,
  `retry_delay`, `submit_body`, `WaitPoll`, `one_job`, `job_page`, ...); the
  async client only awaits and sleeps.
- The core is built with `max_retries=0`. Retries belong to `_call` (429, 5xx,
  connection failures only); never re-enable the core's, it retries 409 too.
- Method names match `@rendobar/sdk` (`jobs.create/get/list/list_all/wait/run/cancel/download/types/schema`).
  Do not rename one without renaming it there.
- Behaviour is defined by the shared conformance scenarios
  (`tests/test_conformance.py`, from rendobar/openapi `conformance/SCENARIOS.md`).
  Every id must pass before a release.
- Webhook verification must agree with `tests/fixtures/webhook-vectors.json`.
- Discover job types with `rb.jobs.types()` (live registry). Never hardcode the list.

- `src/rendobar/agents/`: `_core.py` holds the four agent tools; `langchain.py`
  and `crewai.py` only wrap them. Tools return errors as data, never raise.
  The adapters need the extras (`.[langchain,crewai]`), which the CI `agents` job installs.
- The public API is `rendobar.__all__`. CI runs `griffe check` against the last
  release tag, so removing or changing anything exported fails the build.
- The deny-list scan is `.openapi/scripts/deny_list.py`, shared by every public repo.

Checks: `pytest`, and `pyright` with the extras installed.
